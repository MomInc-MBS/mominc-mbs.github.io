# Earlier architecture choices and open alternatives

## Historical proposals

The core architecture introduced specialist communities; immediate/domain/episodic/procedural/collective memory; replaceable components; and four communication channels. The foundation expanded this into a catalog of 100 code/model resources and 30 primary papers.

| Candidate | Prior intended role | Evidence status here |
|---|---|---|
| LAYA | Routing and structured decisions | Local environment prepared; service was offline |
| Ruflo | Replaceable orchestration adapter | MCP routing responded in prior inventory |
| NCM | Concept-oriented processing research | Proposed branch; no HIVE trial recovered |
| Shared-base adapters | Efficient specialization | Proposed comparison arm |
| Independent backbones/heads | Isolated learning ownership | Tiny independent MLPs tried; LLM arm not established |
| Symbolic tools | Exact calculation and verification | Implementation direction; integrated result not established |

## Preserve the choices

Keep shared, independent, and hybrid organizations. Distinguish prompt roles, adapters, model backbones, deterministic tools, and memory records when counting experts. Multiple names do not establish independent reasoning or independent errors.

## New path

Wrap existing components behind typed interfaces. Pin exact versions and check observed capabilities before using historical descriptions. Reuse useful Ruflo functions while keeping HIVE's journal and evaluation authoritative. Reassess LAYA's actual engine; do not assume an old DeBERTa description still applies.
