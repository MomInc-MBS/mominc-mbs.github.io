SOL, Grok, and Nemotron implementation workflow

Prior plan, not completed execution

The November 19 handoff assigns:

Role Ownership
SOL Architecture, sequencing, integration, acceptance
Grok Connectors, software interfaces, API checks, peer review
NVIDIA Nemotron Contracts, memory, diagnostics, watchdogs, independent checks

Each coder uses a separate Git worktree. Assignments declare allowed paths, inputs, interfaces, acceptance criteria, resource limits, reviewer, and evidence to return. Roles can be reassigned after measured capability checks.

Preserve the dependency order

  1. Inventory and contracts.
  2. Runtime, capability registry, journal, and adapters.
  3. Progress supervision and verified recovery.
  4. Task arena, separate truth engine, and baselines.
  5. Learning staging, candidate evaluation, promotion, and rollback.

The foundation-first restriction deferred autonomous weight updates; it did not remove learning from HIVE's goal. The broader v0.1 plan requires a demonstrated parameter update on unseen variants, with retained prior skills.

New path

Give these same roles the research-vault import, graph indexing, evidence audit, sleep experiments, and runtime tickets. Verify exact provider/model endpoints before assigning execution. Installed coding CLIs do not establish that SOL, Grok, or Nemotron is reachable or running locally.

A completed ticket reports a commit, executed checks, observed outputs, blockers, and resource use. No endpoint means a truthful blocked ticket, not a fictitious run.
