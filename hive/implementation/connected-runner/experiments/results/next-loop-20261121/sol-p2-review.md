## Blocking findings and minimal fixes

1. **Source-conditioned attribution is absent.** `governor.decide` attributes using category and runtime `source_hash`; `Executor._decision` supplies `code_version().source_sha256`. This identifies executing code, not independent input/source family. `task_hash` does bind the whole task, including input and evaluator name, but cannot identify shared-source leakage across different tasks or independently identify evaluator implementation/reviewer. Current v3 route rule duplicates v2 for every mode and category. A new version can legitimately add auditable semantics without changing route choice, but current extra receipt fields do not provide the requested source conditioning. Minimal fix: define a versioned, validated development-source identity and evaluator identity contract, propagate source/input/verifier hashes into P2 attribution and comparison records, and keep runtime-source identity explicitly separate. Either implement source-conditioned behavior or clearly document v3 as attribution-only pending that behavior; preserve v1/v2 snapshots and bytes of receipts.

2. **Missing-verifier protection is simulated only.** `_route_checks` checks task permissions, scope, budget and pinned models, but never probes correct verifier availability. The P2 test passes `route_checks={'tool': 'independent verifier unavailable'}` directly into `decide`, which proves only the generic filter. Independent real-Executor negative replaced verifier with an unavailable exception: tool remained eligible, executed, consumed one cycle, and only then returned invalid verification. This fails the WP3 eligibility-before-scoring requirement; it does fail closed against successful verification/feedback. Minimal fix: add an explicit verifier capability/integrity gate in Executor before route selection and a caller-level negative asserting zero dispatch/reservation when verifier is unavailable.

3. **Saved-output replay ignores decision receipt integrity.** `inspect_evidence` reruns verifier but does not load `decision_ref`, compare the embedded decision, or verify that task/route/config/policy identities agree. Independent negative corrupted decision artifact to `{}`: direct Store read rejected hash mismatch, while `inspect_evidence` still returned accepted saved output. Output replay is valid, P2 attribution replay is not established. Minimal fix: v3-only replay validation dereferencing hashed decision_ref, equality with embedded receipt, and task/route/config/policy/source/evaluator identity consistency. Preserve historical receipt replay explicitly; add mismatched and missing receipt counterexamples.
