## 6. Controlled evolution experiment

**Primary question:** Does retaining independently verified discoveries produce cumulative, transferable benefit beyond a frozen HIVE under comparable resource constraints?

| Arm | Behavior |
|---|---|
| Control | Frozen incumbent policy, model configuration and relevant architecture; normal task execution |
| Evolutionary | Same starting configuration; bounded mutations and retention of independently verified discoveries |
| Optional ablation | Same search budget, but no cross-task discovery retention; isolates the effect of persistent learning |

Before running, preregister task families, development/validation/held-out source splits, seeds or sampling plan, evaluator version, budget per arm, primary metric, minimum practically useful effect, safety conditions and stopping rules. Use paired task comparisons and repeated trials where feasible; document uncertainty and any nondeterminism. Reserve sealed transfer tasks for the final evaluation; do not optimize on those results. Include mutation/search overhead when comparing cost. Report matched-budget and, if useful, matched-quality cost comparisons separately.

Measure:
- Independently verified task success and error categories.
- Total inference and tool cost, including mutation generation, failed experiments and verification.
- Input/output/cache-read/cache-write tokens, wall-clock latency, and context overhead.
- Restart durability and reuse of registered discoveries.
- Transfer to new source-disjoint tasks and degradation on unrelated tasks.
- Behavior under approved pressure scenarios, including resource constraints, noisy evidence and component failure.

Record every attempt, including failures and aborted runs. An improvement is only accepted if it meets preregistered criteria with no disqualifying safety or verification regression. If the control wins, or the comparison is inconclusive, report that outcome. No metric gaming, test leakage, self-scoring or post-hoc threshold changes. The pilot is not itself Level B unless it independently satisfies the full existing Level B contract, including preregistration and sample requirements.

## 8. Mandatory context-window and token-cost management

This requirement applies to all HIVE experiments, Claude orchestration, Nemotron work, reviews, retries and future branch handoffs. Integrate with existing controls rather than adding a competing accounting system.

- **Bounded packets:** include objective, allowed scope, exact relevant paths/symbols, constraints, evidence, test command, budget and definition of done. Retrieve additional material on demand. Do not attach the full master research archive to every call.
- **Starting defaults (configurable; stricter existing limits prevail):** target 8k tokens for normal worker input packets; soft ceiling 16k; reserve output and safety headroom; exception requires explicit justification and approval before exceeding configured hard budget. These are packet targets, not assumptions about model context capacities.
- **Rolling checkpoints:** target a 1k-token summary, including completed work, current state, changed paths, tests, next action, open risks and durable artifact pointers. Checkpoint at phase boundaries and before compaction/handoff. Start fresh task contexts rather than perpetually appending history.
- **Budget preflight:** require explicit per-task and per-campaign token, cost and time caps before paid dispatch. No new paid run with unknown/unapproved caps. Use atomic reservations and stop new work on exhaustion; never silently reset the budget on retry or restart.
- **Cache economics:** meter cached-read and cached-write tokens and actual provider charges separately from uncached input and output. Cache hits are not free by assumption. Compare repeated prefix replay against compact fresh-context retrieval using measured cost and quality; prefer the cheaper valid strategy, not maximum cache hit rate.
- **Selective retrieval:** index artifacts, use small references and relevant snippets, deduplicate shared material, and avoid repeating large logs or test output in prompts. Store complete evidence outside context.
- **Escalation:** on context pressure, checkpoint, summarize, or split tasks; on persistent failures, stop repeated retries and report the blocker. Never bypass security or evaluation to save tokens.
- **Telemetry:** record worker/role, model, task, run ID, input, cached-read/write, output, estimated vs actual cost, latency, retries, result and evidence pointer. If a provider does not expose a metric, mark it unknown rather than estimating it as zero. External coding-agent telemetry must be distinguished from HIVE runtime telemetry.
- **Efficiency acceptance:** compare against a matched baseline, report verified tasks per dollar, cost per accepted improvement, context tokens per verified task and repeated-context overhead. Require no loss of correctness or safety. Publish measured savings or lack thereof; do not claim target reductions as results.
