# Security quarantine: known verification / Git / dispatch gaps

Status: open items only. Each entry names why it is not fixed, the control that bounds it today and the exact condition that lifts it.
Items fixed in the slice-D security pass (DF_REVIEW 1-4, D_REVIEW 5/8/9/11) are listed in `build/v04x/SEC_WORKER_REPORT.md`, not here.
"Quarantined" means: known, bounded, not relied on for any claim above its stated ceiling.

## Slice D: verification and Git

| id | sev | gap | why not fixed | compensating control | lift when |
|---|---|---|---|---|---|
| SQ-1 | LOW | **Store-writer trust limit: `ooda verify` is unkeyed.** A writer who can rewrite the OODA chain, run-state, artifacts, `exp:<id>:frozen` and the receipt can build an internally consistent forged store. | Needs a key or an external append-only record; there is no key custody decision from the owner and no external ledger to anchor to. | `ooda verify --manifest <file>` anchors the frozen manifest and the frozen allowlist hash to files **outside the store**. The frozen verifier is re-run on the stored bytes. The frozen module-byte hashes are rechecked. Replay refuses a changed frozen manifest. Receipts and REPORT.md are committed to git. | The owner approves a signing key (or a git-committed receipt comparison is made part of verify), and `verify` rejects an unsigned receipt. |
| SQ-2 | LOW | **`anchored` is opt-in.** `ooda verify` without `--manifest` still returns `ok: true` with `anchored: false`. Replay's embedded `evidence` block is also unanchored (`run()` already compares the supplied manifest to the frozen one, but not to the canonical allowlist). | Making it mandatory breaks the stores committed before this pass and the fixture-based tests. | The output carries `anchored: false` explicitly. Anything above "internally consistent" must use `--manifest`. | Every consumer (report, release gate) passes `--manifest`; then make it required. |
| SQ-3 | LOW | **`ooda run --allowlist <file>` is still accepted.** A run registered under an override allowlist is not refused. | It is needed by the network-free fixture tests. | The override's hash is frozen (`allowlist_sha256`), and `ooda verify --manifest` reports `anchor_allowlist_is_canonical: false` for such a run. | Tests move to an env-gated override, or the flag is removed. |
| SQ-4 | LOW | **Blob fetch is size-bounded only after the fact.** `git fetch` cannot be told to abort mid-transfer, so the pack cap (`max_bytes + 64 KiB + 512 B/file`) fails closed *after* download. The trees-only commit fetch has no pre-fetch size bound either. | Git has no client-side transfer limit; the v2 `object-info` size query is not available on the allowlisted host. | The commit is shallow (`--depth=1`) and trees-only. The blob oid is resolved locally and **must equal the frozen `expected.blob_sha` before it is fetched**, so the blob size is fixed by a pinned oid. The 90 s timeout applies. The allowlist pins exact repos and commits. | A host or git feature that reports object size before transfer, or a streaming fetch with a byte cap. |
| SQ-5 | LOW | **Fetch-by-blob-oid has no fallback.** It works on github.com (measured: 2 requests, 2751 B / 2967 B of packs against 5870 B / 4346 B before). A host that refuses a bare blob want-line makes the run end `OBSERVATION_PERMANENT`. | github.com is the only allowlisted host. The "fall back to blob:limit" path was not needed and would reintroduce the over-fetch. | The failure is honest and terminal. Nothing is silently fetched more broadly. | A non-GitHub source is added to the allowlist: probe it first, then add a measured fallback or refuse the source. |
| SQ-6 | ~~LOW~~ **LIFTED** | Repo-local config guard ran only before a network fetch. | — | **Fixed (conductor, post-FINAL_REVIEW):** `_read_blob` runs `local_config_violations(repo, url)` before any local read; promisor keys accepted only for the exact allowlisted URL (FINAL_REVIEW #6). The FINAL_REVIEW #1 gap (slice E read outside the hermetic env, 5 uncounted lazy fetches) is fixed: compare now reads the driver's stored, sha-checked observation and makes zero git calls (E_run2: 4 requests = 4 packs). | — |
| SQ-7 | LOW | **The freeze covers `experiment_verify.py` and `experiment_tool.py` as raw bytes only.** It does not cover the interpreter, the stdlib `csv`/`re` modules or the driver itself. A CRLF/LF checkout change or any edit to either module makes `verify` of earlier stores fail (intended; the failure is loud). | No mutability manifest yet (slice G). | Function-source hashes are still frozen as before. `verify` reports `verifier_module_is_frozen_one` / `tool_module_is_frozen_one`. | Slice G lays down the `frozen`/`gated`/`free` manifest and a pinned-interpreter record. |
| SQ-8 | NIT | **Committed stores `D_run/store` and `D_run2/store` remain in git** (bare repos, packs, sqlite). | They are existing evidence and are not rewritten. | `.gitignore` now excludes every future `build/v04x/D_run*/store/`. D_run3's store stays on disk only. | The owner asks for the history to be pruned or archived. |

## BC_REVIEW lows 4-8 (slices B and C: ledger / model route / adapter)

None of these files was in scope for the slice-D security pass; they are quarantined, not forgotten.

| id | sev | gap | why not fixed | compensating control | lift when |
|---|---|---|---|---|---|
| BC-4 | LOW | `model_route.py:74`: the route log's `executed_model` means "admitted", not "executed". | BC-5 | LOW | Hot-path cost is O(n): `model_route.py:105` and `:63` scan the whole route log twice, and `usage_ledger.py:131` parses the whole ledger under the lock on every `begin`. | BC-6 | NIT | The executed-route order is undocumented (barrier → role → preflight → reserve → digest → transport), and so is why digest-after-reserve is safe (the pre-transport `abort`). | Documentation only. | The tests exercise the order. | A header comment in `model_route.py` states it. |

| BC-8b | LOW | An adapter built with `gate=None` skips every gate. | Production paths always inject a gate (`experiment_runner.py:99`, `orchestrator.py:157`). | The only two construction sites pass a gate. | Construction without a gate is made an error. |
| BC-8c | LOW | `max_requests` is not part of the ledger reservation. It relies on `worker_lock` per store.
