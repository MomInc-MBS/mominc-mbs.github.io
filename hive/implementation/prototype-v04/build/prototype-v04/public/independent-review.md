# Independent v0.4 source review

Review is read-only and based on the mutable working tree before freeze. Findings require recheck against the final frozen source. No inference performed.

1. **STOP output path** — `src/hive/structured_data.py` sets `STOPPED` when an enqueued task sees STOP or a retry-ready task cannot run, but then unconditionally enters `_make_outputs`. For a new output file, `_atomic_output` raises `RuntimeError` when STOP exists. Counterexample: create STOP in a fresh store, invoke a valid structured inventory mission: it cannot return and durably record its intended STOPPED result. Partial output commits before a mid-write STOP also need an explicit safe recovery policy. Recommended: return/persist a recoverable stopped state without committing terminal output; verify a resumed operation, including a STOP between output files.

2. **Interrupted inference can dispatch twice** — `Store.recover` requeues dead RUNNING work and conservatively charges its reservation. `run_structured_mission` invokes `run_one` on that QUEUED job, and the executor dispatches again if aggregate caps permit. Counterexample: terminate a classification worker after dispatch but before its evidence is durable, with an approval allowing more than one request. A resume can consume a second call. Preserve a durable dispatch marker and require reconciliation when outcome is unknown; replay a completed receipt without dispatch. Verify with a fake adapter, not live inference.

`inspect_evidence` does rerun the verifier against saved output. The DAG checks nonsynthetic VERIFIED dependencies, hashes bound data, re-enters terminal stages and checks immutable finish receipts. Console checks loopback host, Origin/Fetch-Site and a bearer token on APIs, and restricts artifacts to allowlisted output paths and hashes. These are code observations, not a comprehensive security certification. Approval validation binds the complete manifest hash, store and allowed root, executor config and model digest, with finite caps. Dynamic adversarial tests and final-source review remain necessary.

3. **DAG STOPPED stage cannot resume at zero retries** — if a child returns STOPPED after its DAG stage starts, the DAG persists `attempts = 1`. On the next invocation, only a RUNNING stage has its attempts decremented. With `max_retries = 0`, the `while attempts <= max_retries` loop never executes, so this stage remains STOPPED even after the operator clears STOP. Add same-attempt STOPPED resume and a DAG-level mid-child STOP regression; preserve the no-redispatch barrier for unknown model outcomes.

4. **Subsequent rollback report can misstate the executed procedure** — when a comparison-winning recovery procedure fails the subsequent mission, the code sets `selected_procedure` to `baseline_v1`, but the recorded subsequent task and result are from the recovery procedure; no subsequent baseline execution occurs. State the executed and next-selected procedures separately, or perform a separately approved fallback. Do not imply the baseline produced that result.

5. **Mutable cached verdict is not bound back to replayed verifier result** — `_evidence_row` confirms the immutable evidence verifier replay matches its recorded verification, but derives pass from the separately persisted structured result's `status` and `machine_verdict`; `_replay_job` does not compare that cached verdict against the recomputed result. A corrupted/modified saved FAILED result can be changed to VERIFIED/passed while immutable evidence remains a valid replayed failure, and learning then treats it as a success. Compute outcome from replayed verifier verdict and validate cached mission verdict against it; add a tampered-store negative regression. Local store operator trust limits the security claim, but independently verified evidence must not rely on an unchecked mutable summary.
